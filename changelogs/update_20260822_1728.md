# 更新日誌 - 2026-08-22 17:28

## 🛠️ 修改與新增功能重點記錄

修復手動調整媒體里程後（無 EXIF 拍攝時間之相片）在動畫播放時所有照片於起點/同一位置連續同播、未依指定里程排序與分散播放的錯誤：
1. **區隔真實 EXIF 拍攝時間與檔案系統備援時間 (`has_exif_time`)**：`MediaItem` 與 `scan_media_files()` 新增 `has_exif_time` 旗標，避免以通訊軟體傳輸或下載時相同的 `st_mtime` 進行錯誤時間比對。
2. **重構打卡點相片分群 (Clustering) 演算法**：僅對路線上實際距離差距極近 (<= 50 公尺) 之相片進行同景點合併，杜絕因檔案建立時間相同而將不同里程之照片強制合併至單一景點播放。
3. **時間軸景點字典覆蓋問題修正**：`cluster_by_spot` 改為映射至清單結構，嚴格依照 `(current_km, matched_index)` 依序播放，並修正畫格邊界以防彈出視窗重疊繪製。

---

### 邏輯變更 (Logic)
* **媒體檔案解析 (`gpx_renderer/core/media.py`)**：
  - `MediaItem` 新增 `has_exif_time: bool = False` 屬性。
  - `scan_media_files()` 僅在 EXIF 或影片中成功解析出拍攝時間時將 `has_exif_time` 標註為 `True`。
  - `match_media_to_ride()` 僅在 `has_exif_time == True` 時嘗試時間配對，其餘狀況優先使用 `manual_distance_km` 或 GPS 座標。
* **渲染時間軸與相片播放排程 (`gpx_renderer/core/renderer.py`)**：
  - `valid_items.sort(key=lambda m: (float(m.current_km), int(m.matched_index)))`：依當前有效里程升冪排序。
  - 修正同站合併判定：計算相鄰照片之 `dist_diff_km`，限制在 50 公尺以內才視為同一打卡景點。
  - `cluster_by_spot` 結構重構為 `dict[int, list]`，避免同點位字典鍵值相互覆蓋。
  - `_draw_media_popups()` 邊界判定改為 `start_frame <= frame_idx < end_frame`，消除交界畫格重複渲染。
